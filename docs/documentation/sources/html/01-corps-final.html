Document de référence sur la construction de Takienta : données, paquets JavaScript et Python, site statique, image et déploiement. Public : mainteneurs, développeurs qui reprennent le projet, relecteurs externes.

1. Vue d'ensemble

Takienta expose la structure administrative du Bénin : 12 départements, 77 communes, 546 arrondissements et 6 pôles de développement. Chaque enregistrement porte sa source, la date du relevé et un niveau de confiance. Le projet est personnel, publié sous licence MIT, sans serveur applicatif, sans base de données et sans compte.

1.4 Chemin d'une requête

 navigateur --HTTPS--> Traefik (réseau gcw-public, certificat Let's Encrypt)
                          |
                          v
                 conteneur takienta-site (nginx, port 8080)
                          |
                          +-- /health      : 200 "ok" (sans journal d'accès)
                          +-- /img/og/     : PNG, cache d'un an, CORS ouvert
                          +-- /img/, /fonts/ : cache 7 jours
                          +-- autres URL   : try_files $uri $uri/ $uri.html, cache 300 s

Les en-têtes de sécurité sont placés dans nginx-securite.conf et inclus dans chaque bloc location : un add_header dans un bloc enfant annule ceux du parent, et l'inclusion rend un oubli visible. Le site n'envoie aucun JavaScript au navigateur.

2. Couches logicielles

2.1 Données : data/

Trois schémas JSON (data/schema/entite.schema.json, poles.schema.json, sources.schema.json) valident les fichiers ; tests/test_schemas.py les applique. Un enregistrement porte id, type, nom, tri, parent, source, releveLe et confiance (officielle, derivee ou provisoire), plus alias pour les communes, provisoire, graphie et libelleLoi pour les arrondissements.

NiveauNombreFormat d'identifiantSource déclarée
Départements12BJ-AK (code ISO 3166-2:BJ)loi-97-028, confiance officielle
Communes77BJ-AK-NAT (3 lettres, 4 en cas de collision)loi-2013-05 (annexe), officielle
Arrondissements546BJ-AL-KAN-04 (numéro séquentiel par commune)loi-2013-05, état de 2013, niveau provisoire
Pôles6PO-NOcommunique-marina-2026-09-23, provisoire

Les identifiants sont figés par deux instantanés (data/identifiants.snapshot.json, 06/10/2026 ; data/identifiants-arrondissements.snapshot.json, 07/10/2026). Un identifiant n'est jamais modifié ni réutilisé ; tests/test_instantane.py et tests/test_arrondissements.py le vérifient.

Le registre data/sources.json compte 7 sources : loi-97-028, loi-2013-05, annexe-loi-2013-05-transcription, decret-2009-202, avocevou-2013, communique-marina-2026-09-23 et iso-3166-2-bj. Les documents qui fondent les données sont archivés dans data/sources/ avec leur empreinte SHA-256. Une copie d'un paquet tiers sous GPL-3.0 reste sur le poste de travail, ignorée par Git (tests/test_tiers_non_suivis.py).

Le calque des pôles (data/poles.json) est daté du 23/09/2026 et marqué provisoire. Les 6 pôles regroupent 13, 14, 15, 18, 12 et 5 communes, soit 77. Le chef-lieu du Grand-Nokoué est vide.

2.2 Pipeline : scripts/

ScriptRôle
construire-donnees.pylit les instantanés, le calque des pôles, l'annexe extraite de la loi et le registre ; contrôle chaque nom entrant contre la liste de référence ; écrit les quatre fichiers de data/. L'option --verifier échoue si un fichier diffère. Aucun appel réseau.
annexe_loi_2013_05.py, arrondissements_donnees.py, libelles_arrondissements.pymodules du pipeline : analyse de l'annexe, rattachement aux communes, graphie des libellés (attestee ou deduite-du-libelle)
extraire-annexe-2013-05.pyextraction de l'annexe avec pdftotext ; lancée à la main, jamais par le build
build-data.mjsécrit packages/js/src/generated/ et _generated.py depuis data/ ; encode les arrondissements sous forme compacte
generer-instantane-*.pyn'écrivent que dans un chemin donné en argument ; servent au test de garde-fou, jamais à régénérer l'instantané figé

2.3 Paquet JavaScript : packages/js

src/index.ts exporte parId, communesDe, arrondissementsDe, polesDe, hierarchie et chercher, ainsi que les listes departements, communes, arrondissements, poles, calquePoles et sources. Quatre points d'entrée par niveau (benin-geo/departements, /communes, /arrondissements, /poles) servent à ne charger que ce qui est utilisé.

chercher ignore accents, casse, tirets et apostrophes, et cherche dans le nom et les alias relevés. Le classement va de l'égalité au contenu (cinq rangs), puis suit le champ tri. Elle n'est ni floue ni phonétique, par choix. Les arrondissements ne sont cherchés que sur demande (niveau) ; l'option dans désigne la commune quand plusieurs villes portent le même nom d'arrondissement numéroté.

La construction utilise tsup (ESM et CommonJS, déclarations de types, minification, cible ES2022). test/paquet.test.ts vérifie que l'import par défaut reste sous 150 Ko, qu'il n'y a aucune dépendance d'exécution ni appel réseau, et que ESM et CommonJS exposent la même API.

2.4 Paquet Python : packages/python

Le paquet benin_geo (src/benin_geo/) expose la même API en snake_case : par_id, communes_de, arrondissements_de, poles_de, hierarchie, chercher. Les données sont dans _generated.py, ignoré par Git et ajouté explicitement au wheel par pyproject.toml (clé artifacts). Le paquet est typé (py.typed) et mypy --strict ne signale rien.

2.5 Parité JavaScript et Python

tests/test_croise.py exécute plus de 3 000 requêtes dans les deux paquets (le côté JavaScript passe par scripts/executer-requetes.mjs, qui lit packages/js/dist) et compare les résultats un à un, ainsi que les deux numéros de version. Modifier chercher d'un seul côté fait échouer ce test.

2.6 Site statique : site/

Le site est produit par un générateur Node sans framework. scripts/build-site.mjs importe un module par page (site/pages/*.mjs), les range dans dist-site/ et écrit robots.txt et sitemap.xml. site/donnees.mjs lit data/ : aucun nombre n'est écrit à la main dans une page, et les tests comparent chaque nombre cité aux comptes réels.

FichierRôle
site/layout.mjscoquille commune : en-tête, navigation, pied de page, feuille de style globale
site/config.mjsidentité du site, indicateurs publie (npm, PyPI), hébergement, date des textes légaux
site/docs.mjstransforme docs/*.md en pages HTML avec marked ; docs/cadrage/ n'est pas publié
site/carte.mjs, communes.mjscarte des départements (accueil), tracés et données partagés par /carte et /comparer
site/emboitement.mjsschéma de l'emboîtement et anatomie d'un identifiant
site/og.mjsvignettes de partage : le build échoue si une page n'a pas la sienne
site/site.test.mjstests du HTML produit (vitest)

Le mouvement (transitions de page, révélations au défilement, survol des cartes) est écrit en CSS seul : @view-transition, animation-timeline et le sélecteur :has(). Tout est coupé sous prefers-reduced-motion, et un état de départ caché n'existe que dans des @keyframes, si bien que rien n'est invisible sur un navigateur qui ne gère pas ces fonctions. Ces règles sont verrouillées par des tests.

2.7 Marque et cartes

brand/tokens.json est la source des couleurs ; scripts/build-brand.mjs écrit les SVG, palette.css et brand/README.md, et scripts/emblem.mjs fournit la géométrie de l'emblème. Les PNG et l'ICO sont rendus à part par scripts/rendre-marque.mjs (Chrome et sips) puis commités. Les polices (Caprasimo et Figtree Variable, licence OFL-1.1) sont hébergées dans brand/fonts/ : le site n'appelle aucun service de polices.

scripts/build-carte.mjs génère assets/carte/benin-departements.svg (12 départements) et benin-communes.svg (77 communes) depuis des contours geoBoundaries archivés dans le dépôt avec leur empreinte. Ces cartes sont des assets du site : tests/test_carte.py échoue si une géométrie apparaît dans data/ ou dans un paquet. Les contours des départements datent de 2012 et ceux des communes de 2007, simplifiés : ils illustrent, sans valeur cartographique. Deux noms du fichier de communes (Kobli, Akpo-Misserete) sont rapprochés à la main de Cobly et d'Akpro-Missérété dans assets/carte/source-communes.json.

data/*.json

3.3 Recherche d'une commune

chercher("seme podji")
  -> normalisation : minuscules, sans accents, séparateurs ramenés à une espace
  -> candidats : départements et communes (arrondissements sur demande)
  -> pour chaque forme (nom, alias) : rang 0 à 4 ou rejet
  -> tri par rang, puis par le champ tri
  -> Sèmè-Kpodji, parce que « SEME-PODJI » est un alias relevé dans la loi

3.4 Carte des communes et comparaison

assets/carte/geoBoundaries-BEN-ADM2_simplified.geojson (77 contours)
  -> build-carte.mjs : rattachement par nom normalisé et alias, plus 2 rapprochements écrits
  -> assets/carte/benin-communes.svg
  -> /carte : survol ou focus d'une commune affiche sa fiche (sélecteur :has)
  -> /comparer : deux listes de boutons radio ; la sélection affiche les cellules du tableau

3.5 Flux vers des services externes

Aucun, ni à l'exécution des paquets ni à la construction : le pipeline se rejoue hors ligne depuis data/sources/. Les seules opérations réseau sont manuelles et hors du build : publication sur npm et PyPI, transfert de l'image vers le serveur, et l'extraction initiale de l'annexe (outil pdftotext sur des fichiers locaux).

4.2 Image et conteneur

Le Dockerfile compte deux étages. Le premier (node:22-alpine) active corepack, installe le seul paquet racine avec pnpm install --frozen-lockfile --filter . et lance pnpm build:site. Le second (nginx:1.27-alpine) copie nginx.conf, nginx-securite.conf et dist-site, et écoute sur le port 8080. Le .dockerignore exclut packages/python, data/sources, les contours bruts et docs/cadrage.

docker-compose.yml déclare le service takienta-site (restart: unless-stopped) et son contrôle de santé : wget -qO- http://127.0.0.1:8080/health toutes les 30 secondes, délai de 5 secondes, 3 essais, 10 secondes de démarrage. Ce contrôle vérifie que nginx répond, pas le contenu des pages. docker-compose.prod.yml remplace la construction par l'image ghcr.io/${GHCR_OWNER:-elodias2001}/takienta-site:${IMAGE_TAG:-main}, branche le conteneur au réseau externe gcw-public, pose mem_limit: 128m et memswap_limit: 192m (commit 15748a8) et déclare les étiquettes Traefik (routeur websecure, TLS, certresolver=letsencrypt, port 8080).

4.4 Intégration continue

.github/workflows/ci.yml se déclenche sur les demandes de fusion et les pushes vers main, et à la demande, puis appelle verify.yml. Le job verify tourne sur Python 3.9 et 3.13 et enchaîne : installation (pnpm install --frozen-lockfile, pip install -r requirements-dev.txt), construire-donnees.py --verifier, pnpm type-check, tests du paquet JS, mypy --strict, pytest packages/python, pytest tests, pnpm test:site, pnpm build:site et python -m build packages/python. Le job image construit l'image sans la pousser.

Aucun workflow de déploiement

Le dépôt ne contient ni workflow de déploiement ni workflow de publication des paquets. C'est voulu (commentaire de verify.yml, AGENTS.md) : un tel workflow serait créé sur demande et ne devrait jamais se déclencher seul sur un push. Le déploiement et la publication se font à la main.

4.5 Déploiement manuel

La procédure n'est pas écrite dans le dépôt. Elle suit quatre étapes dans cet ordre :

  1. le nom de domaine est créé dans le DNS avant tout démarrage, car Traefik demande le certificat Let's Encrypt dès que le conteneur démarre ;
  2. l'image est construite pour linux/amd64, le poste de travail étant en arm64 ;
  3. elle est transférée sur le serveur sans passer par un registre ;
  4. le conteneur est recréé avec docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d, dans le dossier du projet.

Les adresses, accès et chemins du serveur ne figurent pas dans cette documentation. Le détail pratique vit dans le manuel technique (§11).

4.6 Variables et secrets

Le dépôt ne contient aucun secret et aucun fichier .env. Les variables lues sont SITE_HOST, COMPOSE_PROJECT_NAME, GHCR_OWNER, IMAGE_TAG (compose) et TAKIENTA_CHROME (rendus d'images) ; SITE_HOST se pose dans le .env du serveur. Les jetons de publication npm et PyPI restent sur le poste de travail, hors dépôt ; le dossier local-secrets/ est ignoré par Git.

4.7 Sauvegardes

Il n'y a pas de base à sauvegarder. Le dépôt GitHub contient les données, les sources archivées et le code. Les archives de sources et la copie tierce non suivie existent sur le poste de travail : leur sauvegarde n'est pas décrite Non déterminé à date.

7.2 Limites de l'outillage

  • Les tests analysent le HTML produit ; aucun test ne pilote un navigateur.
  • La couverture de code n'est pas mesurée.
  • Aucun audit de dépendances (commande ou job) n'est défini.
  • Les en-têtes de production n'incluent pas HSTS, et la version de nginx est exposée.
Frontières de responsabilité

L'hébergement partagé, le DNS et les comptes npm et PyPI relèvent d'Elodias Adimou. Les textes de loi sont la source des données ; le dépôt n'en est que l'archive.
